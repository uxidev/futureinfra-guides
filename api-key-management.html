01 · API 키 관리

API 키를 만들기 전에 정할 세 가지

4분 읽기 · 공개 문서 확인 2026-10-02

API 키 하나를 모든 작업에 돌려 쓰면 문제가 생겼을 때 어느 연결을 끊어야 할지 찾기 어렵습니다. 키를 만들기 전에 어느 조직의 일을 할지, 무엇을 할 수 있어야 하는지, 얼마까지 쓸지를 정해 두세요.

1. 작업과 조직을 먼저 맞춥니다

FutureInfra의 API 키는 발급한 조직 하나에 연결됩니다. 개발용 자동화와 운영 작업은 이름을 구분하고, 조직이 여러 개면 각 조직의 키를 따로 관리합니다. 이름에는 개발-조회처럼 용도를 적고 실제 키 값을 넣지 않습니다.

연결 전에 적어 둘 메모

조직 이름 / 사용할 프로그램 / 필요한 작업 / 관리 담당자 / 월 한도

2. 필요한 권한만 선택합니다

목록을 읽는 도구에 생성·변경 권한까지 줄 필요는 없습니다. 먼저 조회로 연결을 확인하고, 실제 작업에 필요한 권한을 추가하는 방식이 관리하기 쉽습니다.

목적확인할 권한
서버·스냅샷·방화벽 조회cloud:read
서버 생성·전원 등 변경cloud:write
잔액·사용량 확인billing:read

이는 대표 예시입니다. 선택할 수 있는 전체 권한과 승인 조건은 공식 MCP 문서와 콘솔에서 확인하세요.

3. 한도와 보관 위치를 정합니다

키별 월 한도는 자동화가 예상보다 많이 실행될 때 지출을 제한하는 장치입니다. 예상 사용량에 맞춰 설정하고 정기적으로 사용 내역을 확인합니다. 실제 키는 공개 저장소·게시글·브라우저에 내려가는 코드에 넣지 말고, 실행 환경의 비밀값 설정에 보관하세요.

Authorization: Bearer <YOUR_API_KEY>

헤더 형식만 보여 주는 예시입니다. 꺾쇠 안의 문구는 실제 키가 아닙니다.

교체할 때는 연결 확인까지 마칩니다

  1. 같은 조직과 필요한 권한으로 새 키를 발급합니다.
  2. 프로그램의 비밀값 설정을 바꾸고 조회 작업으로 연결을 확인합니다.
  3. 사용하던 연결이 모두 전환됐는지 확인한 뒤 이전 키를 폐기합니다.
  4. 감사 로그와 사용량에서 예상한 작업만 실행되는지 확인합니다.

공개된 곳에 키를 붙여 넣었다면 노출된 키로 취급해 폐기·교체합니다. MCP를 브라우저로 연결할 수 있는 환경에서는 OAuth 연결을 먼저 검토하면 키를 직접 복사하는 일을 줄일 수 있습니다.

확인한 공식 안내

아래 공개 문서를 바탕으로 작업 순서를 정리했습니다. 서비스 조건이 바뀌면 최신 공식 안내를 확인하세요.

  • FutureInfra API 인증 안내
  • MCP 권한·조직·키 폐기 안내
