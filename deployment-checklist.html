02 · 배포 전 확인

도커 앱을 공개하기 전, 여섯 가지 확인

4분 읽기 · 공개 문서 확인 2026-10-02

이미지가 만들어졌다는 결과만으로 배포 준비가 끝나지는 않습니다. 어떤 버전을 올릴지, 필요한 설정이 있는지, 데이터가 어디에 남는지를 먼저 확인하면 공개 직전의 시행착오를 줄일 수 있습니다.

올리기 전에 확인할 네 가지

  1. 이미지 버전을 고정합니다

    latest 대신 변경 이력을 추적할 수 있는 버전 태그를 사용합니다. 배포 기록에 이미지 이름과 버전을 남기고 이전 버전도 확인할 수 있게 보관하세요.

  2. 실행에 필요한 설정을 정리합니다

    데이터베이스 주소, 외부 API 설정처럼 앱이 요구하는 항목을 목록으로 만듭니다. 실제 비밀값을 이미지나 공개 문서에 넣지 않습니다. FutureInfra 앱의 비밀값은 저장 후 다시 열람할 수 없으므로 원래 값을 관리할 위치도 정해 둡니다.

  3. 이미지를 가져올 권한을 확인합니다

    비공개 이미지라면 저장소 접근 설정이 필요합니다. 이미지를 내려받는 데 필요한 읽기 권한으로 토큰을 준비하고, 앱 코드가 사용하는 API 키와 용도를 구분합니다.

  4. 데이터의 보관·복구 방법을 확인합니다

    컨테이너가 다시 배포돼도 남아야 하는 파일은 볼륨 등 영속 저장 위치를 사용해야 합니다. 앱의 데이터 경로, 볼륨 연결, 별도 백업 여부와 복구 순서를 함께 기록합니다.

배포 후에는 두 가지를 더 봅니다

  1. 공개 주소에서 핵심 기능을 실행합니다

    주소와 HTTPS가 열렸는지 확인한 뒤 첫 화면만 보지 말고 핵심 기능까지 점검합니다. 예를 들어 입력 → 처리 → 결과 표시 순서로 한 번 사용해 보세요. 관리 화면과 민감한 기능에 의도한 접근 제한이 적용됐는지도 확인합니다.

  2. 실패했을 때의 대응을 준비합니다

    오류 로그를 확인할 담당자, 이전 이미지 버전, 데이터 복구 위치를 적어 둡니다. 동작하는 버전과 현재 버전의 차이를 추적할 수 있어야 원인을 좁힐 수 있습니다.

정지와 삭제를 구분하세요

FutureInfra의 앱 정지는 주소와 데이터를 유지하며 실행 시간 요금만 멈춥니다. 슬롯·볼륨 비용은 계속 부과될 수 있습니다. 앱을 삭제하면 접속이 끊기고 볼륨 데이터도 사라집니다. 비용을 확인하기 위해 데이터까지 삭제하는 일이 없도록, 실행 전에 대상과 영향을 다시 확인하세요.
